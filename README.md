# inflection-repair-env

A very small RL environment built from the open-source
[`inflection`](https://pypi.org/project/inflection/) library (MIT): an agent
repairs or implements parts of the library, and an objective, differential
grader scores the result. It is built to be hard to game cheaply.

- **Scope note:** [docs/SCOPE.md](docs/SCOPE.md)
- **Results, including the exploit attempts:** [docs/RESULTS.md](docs/RESULTS.md)
- **AI tools used:** [docs/AI_TOOLS.md](docs/AI_TOOLS.md)

## Tasks (Harbor format)

```
tasks/<task>/
  instruction.md          what the agent is told
  task.toml               metadata and timeouts
  environment/Dockerfile  python:3.12-slim + the buggy library in /app
  solution/solve.sh       oracle fix
  tests/test.sh           verifier: writes /logs/verifier/reward.txt
  tests/grade.py ...      hidden grader (never visible to the agent)
```

| Task | Difficulty | Reward |
|---|---|---|
| `fix-ordinal` | easy | binary |
| `fix-case-conversion` | medium | binary |
| `implement-parameterize` | hard | binary |
| `restore-irregular-plurals` | stretch | partial credit |

The task directories are generated by `tools/build_tasks.py` from
`upstream/inflection.py` plus an exact list of bug edits per task. Change
`common/` or the task specs, then rebuild.

## Setup

Python 3.10+ is all the local path needs. The grader is standard library
only; pytest is used only by the visible tests and the exploit demo.

```bash
python -m pip install pytest
```

## One command to run

Create a fresh workspace (the equivalent of `/app`) for a human or an agent to
work in:

```bash
python envctl.py reset fix-ordinal      # -> workspaces/fix-ordinal/
```

To have a free local model attempt it (needs [Ollama](https://ollama.com)):

```bash
python agent/mini_agent.py fix-ordinal --model qwen2.5-coder:7b
```

## One command to grade

```bash
python envctl.py grade fix-ordinal      # grades workspaces/fix-ordinal/
```

Other useful commands:

```bash
python envctl.py baseline               # every untouched task -> expect 0.0
python envctl.py oracle fix-ordinal     # reference fix -> expect 1.0
python exploits/run_exploits.py         # exploit table in docs/RESULTS.md
```

## Docker

```bash
python tools/docker_check.py fix-ordinal --oracle      # expect REWARD=1.0000
python tools/docker_check.py fix-ordinal --exploit e4  # expect REWARD=0.0000
```

With [Harbor](https://github.com/laude-institute/harbor) installed:

```bash
harbor run -p tasks/fix-ordinal -a oracle
```

## How the grader resists gaming

See the top of [`common/grade.py`](common/grade.py) and
[docs/RESULTS.md](docs/RESULTS.md). In short, the grader:

- ignores the visible tests and uses hidden checks;
- draws fresh random inputs on every run and compares them with the pristine
  reference (differential testing);
- copies only the one graded file into a clean room and runs it in a
  separate `python -I -S` interpreter;
- compares results in a process that never imports agent code;
- uses guard checks on every other function, so regressions score 0;
- in Docker, runs agent code as `nobody`, with the tests directory unreadable.

## Extending this to a real customer codebase (stretch note)

Use the same three ingredients: a pristine revision, a scripted defect, and an
oracle. In a customer repository the oracle is usually the customer's own
test suite, run at the fixed commit, plus differential checks against the
pristine build wherever the code is deterministic. The work then becomes:

- harvesting realistic defects from git history (revert real bug-fix
  commits), not only synthetic ones;
- containerising the build once per repository;
- filtering out tasks whose tests are flaky or under-specified (run the
  oracle N times, and drop tasks the untouched code already passes);
- keeping the verifier outside the agent's container.

Confidentiality changes the contamination story too. Private code is unlikely
to have been memorised, which is part of its value to a lab.
